# UI-автотесты интернет-магазина «Дом Диванов»

Учебный проект автоматизации тестирования пользовательского интерфейса сайта [domdivanov64.ru](https://domdivanov64.ru/) с использованием Playwright Test, TypeScript, Page Object Model, Winston и Allure. Автотесты разработаны на основе ранее подготовленных тест-кейсов.

## 1. Реализованные проверки

**Авторизация**

- `ТК-А-01` — успешный вход по электронной почте и паролю; проверка авторизованной сессии и данных аккаунта.
- `ТК-А-02`–`ТК-А-06` — пять параметризованных негативных сценариев: пустой идентификатор, пустой пароль, некорректный формат email, несуществующий пользователь и неверный пароль. Проверяется отказ в авторизации и отсутствие авторизованной сессии.

**Сквозной сценарий**

Поиск дивана «Кант 2», открытие карточки, выбор ширины и обивки, добавление товара в корзину, проверка товара и количества, переход к оформлению, выбор самовывоза и оплаты наличными, проверка пересчёта суммы при изменении количества, проверка доступности формы оформления.

**Ограничения покрытия:**

- Сквозной сценарий **не отправляет заказ** на действующий сайт, поэтому не проверяет факт его создания, номер заказа и итоговое подтверждение. Письменное требование технического задания о создании заказа остаётся невыполненным; отказ от отправки необходимо согласовать с преподавателем как исключение для учебного тестирования.
- При некорректных данных сайт не всегда отображает явное сообщение об ошибке авторизации. Автотесты проверяют отсутствие сессии, но не подтверждают текст ожидаемой ошибки. Этот пункт ТЗ покрыт не полностью.

## 3. Технологии

- **Playwright Test + TypeScript** — автоматизация UI и запуск тестов.
- **Page Object Model и BaseElement** — организация работы со страницами и элементами интерфейса.
- **Winston** — журналирование выполнения сценариев.
- **Allure Playwright / Allure Report** — отчёты, шаги и диагностические вложения.
- **dotenv** — загрузка переменных окружения из `.env`.
- **Chromium, Firefox и Microsoft Edge** — браузеры для тестирования.

Зависимости перечислены в `package.json`. Для воспроизводимой установки вместе с проектом следует передавать `package-lock.json`, поскольку записи с `^` в `package.json` допускают обновление версий.

## 4. Подготовка окружения

Требуются Node.js, npm и установленный Microsoft Edge для проекта `edge`.

1. Из корневой папки проекта установить зависимости:

   ```powershell
   npm ci
   ```

   Команда требует наличия `package-lock.json`. Если его нет, один раз выполните `npm install` и сохраните созданный файл блокировки зависимостей.

2. Установить браузеры, управляемые Playwright:

   ```powershell
   npx playwright install chromium firefox
   ```

3. Создать в корне проекта файл `.env`:

   ```dotenv
   TEST_EMAIL=example@example.com
   TEST_PASSWORD=your_test_password
   BASE_URL=https://domdivanov64.ru
   ```

   Указать данные отдельного тестового аккаунта. `BASE_URL` необязателен: по умолчанию используется адрес из `playwright.config.ts`.

Файл `.env` с действительными учётными данными **нельзя публиковать или передавать вместе с проектом**. Он исключён в `.gitignore`. Перед запуском необходимо убедиться, что сайт доступен, тестовый аккаунт работает, а используемый в сценарии товар доступен в каталоге.

## 5. Запуск автотестов

Все команды выполняются из корневой папки проекта.

```powershell
# Все тесты во всех настроенных браузерах
npx playwright test

# Набор Smoke
npx playwright test --grep "@smoke"

# Набор Regression
npx playwright test --grep "@regression"

# Сквозной сценарий только в Chromium
npx playwright test autotest/criticalPath.spec.ts --project=chromium

# Стандартный HTML-отчёт Playwright
npx playwright show-report
```

В проекте **7 тестовых сценариев**: 1 позитивная авторизация, 5 негативных проверок и 1 сквозной сценарий. При запуске каждого сценария в трёх браузерах выполняется **21 проверка**. Это количество запусков, а не гарантия успешного прохождения или полного соответствия ТЗ.

Конфигурация предусматривает последовательное выполнение (`workers: 1`), общий тайм-аут теста 60 секунд, ожидание проверок 10 секунд, ожидание действий 15 секунд и навигации 30 секунд. Адрес сайта можно переопределить переменной `BASE_URL`, а браузер выбрать через `--project`.

## 6. Allure и диагностика

После запуска тестов сформировать и открыть Allure-отчёт:

```powershell
npx allure generate allure-results --clean -o allure-report
npx allure open allure-report
```

Чтобы **перед демонстрацией** получить отчёт только по актуальному набору Regression, в PowerShell выполните команды в следующем порядке:

```powershell
if (Test-Path .\allure-results) {
    Remove-Item .\allure-results -Recurse -Force
}

npx playwright test --grep "@regression"
npx allure generate allure-results --clean -o allure-report
npx allure open allure-report
```

В Allure отображаются результаты тестов, шаги, группировка по функциональности и диагностические вложения. При ошибках негативной авторизации и сквозного сценария предусмотрены скриншоты с маскированием полей; в позитивной авторизации снимки отключены из-за риска раскрытия персональных данных, а причина их отсутствия прикрепляется к результату теста. Автоматическая запись трассировок и немаскированных скриншотов отключена.

Перед передачей отчёта необходимо проверить логи и вложения на наличие конфиденциальной информации. Маскирование полей не скрывает персональные данные, которые сайт отображает обычным текстом вне замаскированных областей.

## 7. Ограничения и условия выполнения

- Проверки выполняются на действующем интернет-магазине, поэтому результаты зависят от доступности сайта и изменений интерфейса.
- Реализован вход по email и паролю. Наличие самостоятельного входа по телефону и необходимость отдельного сценария требуют уточнения.
- Не все негативные сценарии сопровождаются сообщением об ошибке на сайте; проверка ожидаемого текста ошибки не реализована.
- Сквозной тест намеренно завершается до отправки заявки, чтобы не создавать реальный заказ. Это ограничение требует согласования с преподавателем, поскольку письменное ТЗ предусматривает создание заказа.
- Playwright по умолчанию использует отдельный браузерный контекст для каждого теста. Независимость серверного состояния аккаунта и корзины от предыдущих запусков необходимо проверять отдельно.
- Используется TypeScript, совместимый с Playwright и основанный на JavaScript. Если список языков в ТЗ трактуется строго, применение TypeScript следует согласовать.

## 8. Демонстрация преподавателю

На демонстрации необходимо показать запуск автотестов, результаты выполнения и Allure-отчёт с шагами и диагностикой. Ограничения из раздела 7 следует озвучить отдельно. **Сценарий без отправки заявки не следует представлять как успешно проверенное создание заказа.**
